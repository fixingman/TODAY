# 15E — web/Trello next-result loop

October 27, 2026. Can authorized implementation and explicitly chose cross-task wording guidance on this device. This extends the existing manual-task web/Trello context component; Gmail, Focus Ask, feelings and other writers retain their own boundaries.

## Mechanism

- Existing **not useful** still hides only the exact card, with Undo/show context. It does not infer why a result missed or send a vote to a writer.
- A hidden card offers **try other context**. That explicit click authorizes one ordinary enrichment lookup for the same unchanged Today task in this focus visit. No automatic call on rating, timer entry, restoration or clearing; at most one replacement request per visit, retaining the existing 26s client / 24s server deadline and three-turn server limit. A failed/empty replacement leaves the old card hidden and recoverable. A new valid card replaces it. The previous source URL, stripped of credentials/query/fragment, is excluded; previous card prose is never sent. Without an old source URL, the writer may abstain rather than manufacture difference.
- **wording** expands an optional native row inside the existing card. **hard to follow** / **too formal**, Undo and clear all set/remove fixed concerns, never an inferred preference. It guides future eligible web/Trello requests for other tasks on this device; accepted cached cards remain unchanged. No immediate rewrite/request. Every guide remains tied to its source task/text/board and exact displayed-card identity. Task edits, deletion, expiry, source-board change and clear remove influence.
- Derived guidance is at most the two whitelisted enum values, recomputed from valid supporting records. No task history, card headline/body, votes from other surfaces, counts, inferred motives or profile is sent. Link clicks, silence, completion and plain hiding stay neutral. Claude Forget and clear-all-memory remove wording support and fence pending guided responses.

## Local data and source safety

Use existing cache v3 and its unchanged 60-entry / 200,000 UTF-8-byte aggregate budget. Add optional `wording: {policy:1, concern, at, expiresAt, cardId}`; concern is one supported enum, dates are finite milliseconds, cardId is a SHA-256 exact-card digest (not anonymization). One current concern per task; no history/store/retention expansion. Expiry is no later than the supporting card's original 30-day deadline and must not extend when a replacement card is cached. Revision replaces the record; clear all deletes all records in this domain. Undo restores only still-eligible supporting owners and is transient for the current displayed result. Old v3 entries remain valid and old hides never become feedback; older clients ignore optional fields and may discard them during a real cache replacement. This local store is absent from backup/sync/Restore, so no remote LWW/clear watermark/schema change is introduced. Restored task text/deletion is still validated before guidance use. Board id is the existing source scope; raw credentials remain transient request fences, not duplicated metadata.

Request ownership captures task/text/source/cache, current wording-support stamp and a local feedback epoch. Recheck after asynchronous preparation, headers/body and before writes; source edits, withdrawn/expired feedback and external cache adoption fence late results. A wording change/clear cannot let an older response replace current state. Cross-tab storage events update controls and fence pending work. No automatic regeneration of existing accepted cards.
