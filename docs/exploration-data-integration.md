## Connect real context

Existing explorations initially keep their earlier scope. **Connect TODAY data**, or the explicit checkbox at creation, authorizes a per-exploration projection. Permission and exclusions live in the canonical Dropbox document, so they are shared across devices. They are not device preferences or a new profile.

`assets/exploration-context.js` reads current manual tasks and supported Memory task records, counted facts and live stable interpretations. It does not call `_memoryForAI()` or ingest the complete appMemory object. Coverage counts, weekly AI readings, feelings, dream stores, mail, Calendar and prior feedback stores are not exploration inputs. A person can deliberately add a chosen checkpoint or describe sensitive material in their own words.

The local selector matches the question and latest saved observation, retains manual order as a tie-breaker, selects at most eight matching records and at most two AI interpretations, and selects nothing automatically when no wording matches. The optional “choose other TODAY records” disclosure exposes other eligible records; deliberate inclusions are shared with the exploration and still obey the eight-record/two-interpretation caps. This supplies a path when the person does not know which words a stored pattern uses. Shared wording is only a retrieval reason, not proof of meaning. Notes lists the exact live references used by a valid reading. Separately, the visible TODAY context disclosure previews the selection and permits source exclusion; its controls remain visible on touch. The context is rechecked at reply time. Opening, reviewing and excluding context never requests AI. Only a deliberate reply, retry or requested experiment does.

Records and counted facts remain distinguishable from earlier AI interpretations in both UI and model input. A reading remains unconfirmed. Completion does not establish benefit. The existing explicit historical task-snapshot path remains available and is labelled as a copy; it is distinct from the live projection.

## Provenance, change and retention

Live source text is read transiently from its existing store. A new reading keeps reference IDs, SHA-256 change-detection fingerprints and the current permission epoch; it does not duplicate a source record as a journal observation. Fingerprints detect change and are not encryption. AI replies may nevertheless quote their inputs: the reply and its history remain part of the exploration until it is forgotten. The connection/privacy copy and clear confirmation say so.

Readings inherit earlier interpretations' source dependencies. Edits, unavailable or expired records, rejected hypotheses, Memory clear, exclusion and connection changes withhold dependent readings and keep them out of subsequent prompts. A missing record on another device may be incomplete sync, so no destructive retirement is written merely because that device lacks it. Sync readiness is checked before projecting records. The Memory clear watermark is part of each fingerprint, preventing old backup rows from restoring a cleared interpretation. Excluding or reconnecting context changes a UUID permission epoch, so re-inclusion does not revive an old reading. Changing the AI provider fences a pending reply but does not erase a stored record.

A completed task remaining in the task store is not offered for a new selection but can still support a previous reading of the same wording. Deleted or aged-out records become unavailable; no automatic task-status journal event or benefit is invented. Other record and aggregate changes may withhold their dependent readings rather than pretending the earlier interpretation has current support.

Requests recheck session, canonical revision, workspace, Dropbox grant, model key/provider, current source fingerprints and explicit cancellation. Source choices and local/synced Memory changes abort affected pending work. The raw observation is already acknowledged in Dropbox; the person can deliberately ask again with current context.

Withholding affects display and future AI input. It does not erase old reply text from the raw Markdown record or export. Both expose the same complete document. **Clear Memory** clears its records and withholds dependent exploration readings; the separate file/history stays. **Forget exploration** revision-conditionally deletes that file and clears working copies; daily tasks remain. Dropbox recovery/version policies remain account-specific.

## Checkpoints and format compatibility

At creation, choose a Markdown checkpoint as opening material. Existing sessions also offer **Notes & sources → Add a checkpoint**. Selection appends its original text to the starting material through the same revision-conditional write; it preserves earlier records, source choices, workspace identity and unknown fields. A new opening-material revision withholds interpretations formed before the addition. Import performs no model request. The file remains capped at 500,000 UTF-8 bytes and oversized additions fail without replacing the document.

The reader accepts native schema 1 and 2. New documents use schema 2; connecting live TODAY data or adding a checkpoint upgrades an existing document to 2. Schema 2 adds `today_context`, `today_sources`, `today_epoch` and `opening_revision` provenance. Evidence citations may resolve to a declared live reference as well as an earlier raw record. The shared policy is `{enabled, epoch, excluded:[], included:[]}`; `included` contains deliberately chosen IDs (at most eight). Each reading carries `today_sources:[{id,signature}]`, `today_epoch` and `opening_revision`. The codec validates reference shapes and preserves unknown fields. Older v3.1 readers reject schema 2 rather than editing it with incomplete withdrawal rules. Use v3.2 or later on all devices that edit an upgraded file. Unknown future major versions remain refused. No personal stage, candidate endorsement or provisional skill state is seeded or migrated.

Model context remains bounded: opening material at beginning/end (12,000 characters), up to twelve included journal records (1,800 each), at most eight live records (1,200 each), a bounded prior reading and its three latest corrections. Long omitted material is marked. Selection is intentionally conservative and lexical; live writing usefulness and more sophisticated retrieval remain real-use judgments.
