| **2.18.15** | **Fix: BUG-046 — Trello board selector re-render loop.** `loadTrelloBoards()` called `renderConnections()` to create the `<select>` element, but `renderConnections()` calls `loadTrelloBoards()` whenever there is a Trello token but no board saved. This created a tight loop: each board API response (~200–500ms) triggered a full panel re-render, which started another fetch, which re-rendered again. On mobile this manifested as the board dropdown and Dropbox buttons flickering continuously and the native picker being dismissed before the user could select. Fix: removed `renderConnections()` from inside `loadTrelloBoards()` — both call paths that reach this function (`renderConnections→loadTrelloBoards` on panel-open, `renderConnections→loadTrelloBoards` after auth) already have the `boardSelect` element in the DOM by the time the board fetch completes. |
| **2.18.14** | **Fix: done-task count inflated by yesterday's sync after midnight (BUG-024 class).** `stat_tasks_done_today` had no companion date stamp, so the same class of bug that hit focus minutes (fixed v2.17.44) also affected the done count. After midnight, the first 7s sync tick downloads yesterday's Dropbox backup (e.g. "3 tasks done yesterday") and `Math.max(0, 3)` restores 3 as today's count — before any tasks are done today. Any tasks completed post-midnight then accumulate on top of the inflated base. Added `stat_tasks_done_today_date` parallel to `stat_focus_mins_date`: set on every increment (triage done, normal checkbox) and on daily reset in `applyNewDayCleanup()`. Backup payload now carries the stamp (fallback `''`, never `_getAppDay()` — same lesson as BUG-024 v2.17.46). `mergeRemoteData()` and the full-restore path now date-guard the done count exactly as they do for focus minutes. |
| **2.18.13** | **Fix: BUG-041 third pass — iOS PWA white flash was the OS launch screen, not the WebView first paint.** The "white → dark → splash" sequence on iPhone home-screen cold launch decomposes as: frame 0 = OS-painted launch screen (white, because no `apple-touch-startup-image` was registered) → frame 1 = WebView first paint (`#0e0e10`, the v2.18.2/v2.18.7 fix working) → splash. The two prior passes only ever controlled frame 1. Added a full `apple-touch-startup-image` set (one solid `#0e0e10` PNG per current iPhone resolution, generated by `scripts/gen-splash.mjs`, precached in `sw.js`) plus the `apple-mobile-web-app-capable` meta. **Gotcha:** iOS caches launch images at add-to-home-screen time — the PWA must be removed and re-added for the fix to take effect; a plain relaunch keeps the old white frame (likely why earlier verification was inconclusive). |
| **2.18.12** | **Fix: Trello age-bucket dimming now updates every 7 s and on wake.** The `data-age-bucket` patch inside `renderTrello()` is purely local and network-free, but it was only called when `syncTrello()` detected a change in `board.dateLastActivity`. Cards whose board had no recent Trello activity never had their opacity updated in the DOM, causing cross-device inconsistency: the device that triggered a Trello sync saw correct aging; the other kept stale buckets until a manual Refresh. Fixed by calling `renderTrello()` unconditionally in `syncAll()` (every 7 s) and in the `visibilitychange` wake handler. |
| **2.18.11** | **Fix: BUG-043 parity — manual tasks un-dim on partial focus too.** The v2.18.8 fix made Trello cards un-dim on any focus session (even Escape without completing), but manual tasks still required a completed pomodoro (`_logSession` → `lastActive`). `closeUI` now also refreshes `lastActive` and removes `data-age-bucket` for manual tasks when any focus time was spent. Both types now align: any engagement un-dims, pomodoro completion is not required. |
| **2.18.10** | **Fix: morning nudge always shows carried-over count.** The AI tier-2 sentence was replacing the rule-based message entirely when cached or when it won the 1s race — silently dropping the count. Rule-based path was unaffected (count is in the text). AI path now prepends `"N carried over · "` when `carriedOver > 0`, so the count is always visible regardless of which tier wins. |
| **2.18.9** | **Fix: PAST zone now shows all tasks.** The list was capped at 20 (`pastTasks.slice(0, 20)`) for "performance" but the count badge always showed the true total — a confusing mismatch for anyone with >20 PAST tasks. Removed the slice; at realistic personal-task volumes the full list renders instantly. |
| **2.18.8** | **Fix: BUG-043 — aged Trello cards now un-dim after any focus session.** Previously `today_trello_focus` (the activity signal for Trello card age) was only incremented when a full 25-minute pomodoro completed or when a task was checked off while focusing. Closing the focus UI early via Escape or task-switch — the common case — never updated the map, so the card stayed dimmed even after genuine engagement. Fix: `closeUI` now marks the card as engaged (`today_trello_focus[id] = 1`) when any focus time was spent and the count is still 0. Guard prevents double-increment if a completed pomodoro or `_focusOnCheck` already logged the session. Instant visual un-dim on close; the 7s Trello patch cycle confirms it. |
| **2.18.7** | **Fix: BUG-041 second pass — white flash on Android/Arc cold start.** v2.18.2 fixed iOS (inline `<html>` bg + `color-scheme:dark` meta) but a white frame survived on **Arc** (Chromium) on Android. Diagnosis: it's a **pre-first-paint frame** showing the browser's default canvas, which is **white in light system mode** (dark mode masked it — user's theme is dynamic). Our dark signals weren't applied early enough by Arc. Mitigation (additive, can't regress): (1) `<html>` inline `background` → `background-color` (the property Chromium's pre-FCP base-color heuristic reads); (2) added inline `background-color:#0e0e10` to `<body>` (heuristic can read body); (3) added `color-scheme: dark` to `:root` in CSS, not only the meta. Honest caveat: Arc's standalone-PWA rendering is partly browser-controlled — if a frame survives, the residue is Arc-side. Verify by forcing light mode + cold-launch. |
| **2.18.6** | **Fix: BUG-044 — delayed focus chime when not in focus mode.** `closeUI(false)` (Escape, task-switch, line 11983) cleared the tick timer + closed the UI/PiP but left `st.running=true` + `st.wallStart` set — a "zombie" session. The `visibilitychange` correction iterates all running states, so on tab return it jumped the zombie's `rem` to ≤0 and called `completeFor` → `playChime()` with no focus UI active = a late, out-of-context chime. (Click-outside already stopped the session before closeUI; the other callers didn't.) Fix: `closeUI` now stops the closing task's session (`running=false, paused=false, wallStart=null`) right after `_trackFocusTime`, centralizing what click-outside did manually. `continueTicking` has no callers (no intended background tick) and PiP is closed by closeUI, so after any closeUI there should be no running session — this is a correctness fix, not a behavior change. Resume-on-reclick (keys on `rem`, line 11667) and focus-minute accounting (keys on `rem`/`tracked`) unaffected. Also fixes a latent "switch task A→B leaves A running." No `_focusUIActive` guard added on the chime (would wrongly mute the legit PiP completion chime). |

| **2.18.4** | **Fix: two Trello bugs.** **BUG-042 (order scramble across devices, worst on a new day):** `trello_order` rides in *every* backup, and `mergeRemoteData` adopted it unconditionally ("remote wins", unchanged since v2.12.28) — so any unrelated write from the other device re-asserted its possibly-stale order. Surfaced hardest at the day boundary, when both devices run `applyNewDayCleanup` → re-fetch → re-sync at once. Added a `today_trello_order_at` ISO stamp (set on reorder, line ~7277), carried in the payload; merge now adopts remote order only if `remote.trello_order_at > local` **or** the device has no local order yet (bootstrap). Empty-string defaults mean an untimestamped old-client backup never clobbers a timestamped local order. Full-restore path carries the stamp too. Additive field — backward compatible, no schema bump. **BUG-043 (aged Trello card won't un-dim after a focus session):** the `data-age-bucket` opacity uses age = `_getCreatedFromTrelloId(id)` (card creation, immutable) for Trello, vs `lastActive` for manual tasks — so manual tasks un-age on activity but Trello cards never could. Now a Trello card with a focus session today (`_getTrelloFocus()[id] > 0`, daily-reset) reads as active → full opacity, in both `taskHTML` and the 7s patch path. |
| **2.18.3** | **Design: nudge consistency pass** (morning + Trello nudge share `.morning-nudge`, so both update). Three changes from a product-design critique: **(1) Alignment** — `.morning-nudge` padding `var(--space-2) var(--space-4)` → `var(--space-2) 0`, so the dot sits flush at the section edge, on the same left line as the `.section-label` above and the task-box edge below (both at 0 inset; `.section`/`.task-list` have no horizontal padding). No `--tracking` token introduced — would orphan the other 13 inline uses; left as a future system-wide pass. |
| **2.18.2** | **Fix: BUG-041 — white flash before dark on mobile cold start** — distinct from BUG-032 (that's the *logo glyphs*; this is the *page canvas*). The dark background lived only in the inline `<style>` (`html,body { background: var(--bg) }`), so the first rendered frame — before the stylesheet parsed — used the UA default **white**. No `color-scheme` hint and no presentational background on `<html>`, and iOS PWAs ignore manifest `background_color` (Android Chrome honors it, which is why it was iOS-only). On warm cache the gap is sub-frame; on mobile cold start it's visible: white → dark → splash. Fix: added `<meta name="color-scheme" content="dark">` (UA paints a dark default canvas pre-CSS) + an inline `style="background:#0e0e10"` on `<html>` (the one literal that paints on frame 1, before CSS vars exist — deliberate Rule 19 exception, documented inline, kept in sync with `--bg`). `theme-color` (line ~311) only tints the status-bar chrome — not the cause. |
