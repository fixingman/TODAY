| **2.25.10** | **Fix: four meeting-chunking bugs (code review of the pipeline).** (1) **Payload over Netlify's 6MB limit** — `MediaRecorder` had no `audioBitsPerSecond`, so browser-default ~128 kbps × 6-min chunks ≈ 7.7MB base64 → every full-length chunk failed, retried once, dropped (6 lost minutes each, masked in short meetings). (2) Retry cross-meeting leak: `_meetingSendChunk` retry re-captured `_mtg` fresh — a discarded meeting's retrying chunk could write items/context into a newly started meeting; retries now reuse the originally captured state (new `priorState` param). (3) Crash on quick Discard: empty-final-chunk branch in `onstop` called `_meetingRenderReview(_mtg)` unguarded — `_mtg` null if Discard beat `onstop`; added guard. (4) Stale "~60s chunks" comments ×3 (module header, `_meetingRecordChunk`, netlify fn header) + `_mtg` shape comment missing `chunkStartedAt`/`finalChunkSecs`/`processingFinalChunk`; Components.md pipeline section updated (bitrate, 6-min, retry semantics) + stale "mine pre-selected" line corrected to v2.25.4 behaviour. |
