| **2.18.18** | **Polish: BUG-032 — smoother splash letter-rise.** The `splashLetterRise` keyframe used easeOutExpo (`--ease-out`, `cubic-bezier(0.16,1,0.3,1)`) over a tiny `translateY(0.12em)` (~11px) distance in `.4s`. | **2.18.15** | **Fix: BUG-046 — Trello board selector re-render loop.** `loadTrelloBoards()` called `renderConnections()` to create the `<select>` element, but `renderConnections()` calls `loadTrelloBoards()` whenever there is a Trello token but no board saved. This created a tight loop: each board API response (~200–500ms) triggered a full panel re-render, which started another fetch, which re-rendered again. On mobile this manifested as the board dropdown and Dropbox buttons flickering continuously and the native picker being dismissed before the user could select. Fix: removed `renderConnections()` from inside `loadTrelloBoards()` — both call paths that reach this function (`renderConnections→loadTrelloBoards` on panel-open, `renderConnections→loadTrelloBoards` after auth) already have the `boardSelect` element in the DOM by the time the board fetch completes. |
| **2.18.14** | **Fix: done-task count inflated by yesterday's sync after midnight (BUG-024 class).** `stat_tasks_done_today` had no companion date stamp, so the same class of bug that hit focus minutes (fixed v2.17.44) also affected the done count. After midnight, the first 7s sync tick downloads yesterday's Dropbox backup (e.g. "3 tasks done yesterday") and `Math.max(0, 3)` restores 3 as today's count — before any tasks are done today. Any tasks completed post-midnight then accumulate on top of the inflated base. Added `stat_tasks_done_today_date` parallel to `stat_focus_mins_date`: set on every increment (triage done, normal checkbox) and on daily reset in `applyNewDayCleanup()`. Backup payload now carries the stamp (fallback `''`, never `_getAppDay()` — same lesson as BUG-024 v2.17.46). `mergeRemoteData()` and the full-restore path now date-guard the done count exactly as they do for focus minutes. |

| **2.18.8** | **Fix: BUG-043 — aged Trello cards now un-dim after any focus session.** Previously `today_trello_focus` (the activity signal for Trello card age) was only incremented when a full 25-minute pomodoro completed or when a task was checked off while focusing. | **2.18.7** | **Fix: BUG-041 second pass — white flash on Android/Arc cold start.** v2.18.2 fixed iOS (inline `<html>` bg + `color-scheme:dark` meta) but a white frame survived on **Arc** (Chromium) on Android. Diagnosis: it's a **pre-first-paint frame** showing the browser's default canvas, which is **white in light system mode** (dark mode masked it — user's theme is dynamic). Our dark signals weren't applied early enough by Arc. Mitigation (additive, can't regress): (1) `<html>` inline `background` → `background-color` (the property Chromium's pre-FCP base-color heuristic reads); (2) added inline `background-color:#0e0e10` to `<body>` (heuristic can read body); (3) added `color-scheme: dark` to `:root` in CSS, not only the meta. Honest caveat: Arc's standalone-PWA rendering is partly browser-controlled — if a frame survives, the residue is Arc-side. Verify by forcing light mode + cold-launch. |
