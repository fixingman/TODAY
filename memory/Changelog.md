| **2.18.2** | **Fix: BUG-041 — white flash before dark on mobile cold start** — distinct from BUG-032 (that's the *logo glyphs*; this is the *page canvas*). The dark background lived only in the inline `<style>` (`html,body { background: var(--bg) }`), so the first rendered frame — before the stylesheet parsed — used the UA default **white**. No `color-scheme` hint and no presentational background on `<html>`, and iOS PWAs ignore manifest `background_color` (Android Chrome honors it, which is why it was iOS-only). On warm cache the gap is sub-frame; on mobile cold start it's visible: white → dark → splash. Fix: added `<meta name="color-scheme" content="dark">` (UA paints a dark default canvas pre-CSS) + an inline `style="background:#0e0e10"` on `<html>` (the one literal that paints on frame 1, before CSS vars exist — deliberate Rule 19 exception, documented inline, kept in sync with `--bg`). `theme-color` (line ~311) only tints the status-bar chrome — not the cause. |
