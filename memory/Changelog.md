| **2.81.3** | **`letgo-return` links the two events instead of counting them side by side.** Can's correction: the point was to know *which task is in the loop*, and v2.81.0 could not say — it counted let-gos and revives in the same window and, to stay honest, refused to say "of them". The log can do better: a let-go and a revive of the same task share an id (`_memoryTextKey`, a hash of the text, identical across devices), so a revive is linked when a let-go of the same id precedes it — anywhere in the log, since the release may predate the window; only the return must fall inside 45 days. Backfilled rows carry synthetic ids and never link. Fires at 2+ linked returns; the release-volume floor is gone because linking replaced it. **Naming without storing text:** `_fetchPoolNudge` hashes the live lists (today, Soon, Past) the same way and passes `taskTexts` `{ id: text }`, so the kind names a revived task while it is still on a list and falls back to counts once it is gone — memory never holds a second copy of what the user wrote. Two evidence shapes: one task cycling twice → *"call the dentist" has gone out and come back 2 times* / *Let go, and back again.*; otherwise *Over 45 days, 2 things you had let go came back — "a" and "b".* Names capped at 40 chars, 3 per line. Fifteen tests for the kind now, 57 in the suite; the nudge suite's no-leak check is unaffected because it looks for the task-list header, not task text. |

| **2.80.4** | **Fix: stale premises in AI context — three leaks of the same class.** Reported from production: the morning nudge said a task was "still waiting after 56 days" when it had been completed the day before. (1) `_updateReturningTasksMemory` rebuilt `returningTasks` from `manualTasks` but never filtered `doneIds` — the only context builder in the app that didn't (`nudge.js:100/105/356`, `about.js:595/649`, `focus.js:313` all do). A task completed yesterday and still present in `manualTasks` kept its full age and was handed to the AI as waiting. (3) `focus.js` filtered `doneIds` but not `pastTasks`, so a stale sync could offer an archived task to the focus question as part of "today's list". **Note on the class:** the model never hallucinated in any of these — it reported exactly what the context said. Stale-premise bugs are therefore invisible to prompt work, and better phrasing only produces a more convincing wrong sentence. Regression tests reproduce the production report directly and were verified to fail without the fix; one of them also caught the first patch landing in `_memoryOnTaskComplete` instead of `_memoryOnTaskLetgo`, because `insights.js` carries two identical `_kStopWords` declarations. Full suite 25/25. |
