No visual styling changed. The accessibility suite now waits for finite entrance motion (preventing false contrast failures on About and focus controls), forces an evening bar regardless of test clock, checks focus isolation and axe, and verifies Review becomes keyboard-focusable again on exit. |
| **2.90.45** | **Fix: triage bar click and double open animation (v2.90.42 follow-up).** (1) Tapping the bar did nothing outside the small Review button: the v2.68.0 accessibility pass moved `onclick` from the bar to the button, but the bar kept `cursor: pointer` and its hover border, and `Components.md` still specifies the whole bar as tappable. `#triageBar` now carries `data-today-click="triage.expand"`; the runtime's nearest-action routing means the button does not fire twice, and the button remains the keyboard control. (2) The sheet dropped and rose again after the morph: the 200ms content-reveal timer removed `triage-morph-opening`, so the panel's base `animation: slideUp` took over mid-open and replayed from off-screen (browser-sampled: top 499px at 209ms → 844px at 226ms, settling at ~500ms). The opening class now stays for the sheet's lifetime and is cleared on close; the reveal timer only removes `triage-morph-active` and is cancelled on minimise/close. `triage-test` adds a case that clicks the bar text and samples the panel per frame (no downward jump, `triageMorphUp` still owning the animation at 260ms, class cleared after minimise) — verified failing on the old code. |
| **2.90.44** | **Fix BUG-099 follow-up: first-open cleanup no longer erases a same-day triage dismissal.** Cold start merges Dropbox before `applyNewDayCleanup()`, so a device last opened yesterday can already hold today's dismissal from another device when cleanup runs; cleanup removed `triage_dismissed` unconditionally and the prompt reappeared. Cleanup now keeps a dismissal dated today and clears only older or invalid dates. `day-lifecycle-test` covers a genuine rollover clearing yesterday's dismissal and the full first-open pull → cleanup → backup sequence with mocked Dropbox. Cold-start splash budget raised 19000 → 23000ms in `performance-budgets.json`. |
| **2.90.43** | **Fix: today's morning line vanished from About after a task was finished.** The nudge staleness guard (`day_nudge_done_count_<date>`) deleted `day_nudge_ai_<date>` as soon as more tasks were done than when the line was written, then relied on regeneration to replace it. Regeneration is not allowed at the init call site and can return nothing (offline, fetch failure, grounding rejection), leaving the key empty — and About's Today block and the Dropbox upload both read that key, so the empty value was pushed and no device could restore the line for the rest of the day. The guard now only skips the stale line in the morning strip; `_raceAINudge` overwrites the key only when a fresh line arrives. A Dropbox merge that brings a different line clears the local done-count stamp, which described this device's line. `nudge-test` 5 now covers: stale line kept without generation, kept after a failed retry with About still showing it, replaced and restamped on success (verified failing on the old code). |
| **2.90.42** | **Triage bar → sheet morph.** The triage pill morphs into the review panel on open and collapses back on minimise: `@keyframes triageMorphUp/Down` scale the panel from the bar's approximate position (`translateY(-72px) scaleX(0.60) scaleY(0.13)`); backdrop fades in via a two-step rAF; panel content is hidden during the morph (`.triage-morph-active`) and revealed after 200ms. | **2.90.38** | **Drag reorder: midpoint-based touch placement and desktop flicker fix.** Touch reordering replaced `elementFromPoint` hit-testing with a midpoint scan (`_findSlot`): each move fires once when the finger crosses a row's midpoint, not every time the DOM shifts after a previous swap. Desktop `dragleave` now checks `relatedTarget` so moving the pointer over child elements inside a long row no longer flickers the accent border off and on; a `dragOver` pointer skips the full CSS clear-and-re-add on every `mousemove`. | **2.90.37** | **Fix BUG-099: completed triage could ask again on another device.** `triageApplyAll()` wrote `triage_dismissed` locally but only uploaded immediately when a task moved or was marked done; an all-`Keep` pass waited for the completion summary to auto-close, so suspending the first device could leave Dropbox unaware. Tests cover immediate all-`Keep` scheduling, local storage, remote adoption, stale-blank healing, and preservation of the local completion. |
| **2.90.36** | **Sunday now surfaces a supported insight, not a dressed-up statistic.** The production line *“You closed out 41 of 206 threads…outlived their relevance—not burnout, just expiration”* repeated the two earlier pool failures: numerically grounded, but opaque and inert. The fix is architectural across all six observation kinds. Each candidate now carries separate `evidence` and a code-owned `insight`: the evidence proves the relationship; the insight states the bounded human reading or lever. Sunday sends the model only the selected kind and insight—the evidence counts remain inside deterministic policy and diagnostics—so the model phrases meaning instead of discovering it from statistics. Output retains earned warmth, wit, and a clarifying metaphor when useful; a candidate-aware guard requires the response to preserve the kind's literal actions and relationship, so both the reported sentence and fluent generic filler are rejected. Policy `earned-v4` allows today's older-policy line to be replaced once. The local audit now uses `survivesGate` for every viable candidate and `selected: true` only for the single winner. Tests cover the candidate schema, bounded readings, payload boundary, semantic anchoring, stale-policy replacement, and one-winner diagnostics. |
