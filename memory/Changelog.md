| **2.91.1** | **Fix BUG-106: three more guards on functions that moved into modules.** The BUG-105 pattern — `typeof _x === 'function' ? Today.use(...)._x() : fallback` where `_x` stopped being a global in the 2026-09-05 refactor — made three features take their fallback every time. The focus companion (`focus.js`) computed every other task's age as 0, so its prompt never said "Nd old" (browser-verified: now sends `"Renew passport" (4d old)`); the weekly reflection's aging list (`about.js`) ignored `createdAt`; and the wake handler (`dropbox.js`) never re-applied the offline banner after sleep. All three now call the module directly; both age sites use triage's `lastActive || createdAt || _getCreatedFromId(id)`. The fourth suspect, `meeting.js:169`, was a false positive — `_getUserNames` is closure-scoped in the same module. `component-contract-test` now fails on any `typeof _x === 'function'` guard whose name is neither declared in the same file nor published as a property; it names exactly these three sites on the old code. |
| **2.91.0** | **Memory panel: AI observations have a lifecycle; KNOWN lists waiting Soon tasks.** Can: KNOWN showed only the counts line, and EPISODIC had grown into a long mix of topic summaries ("house painting", "invoices"), near-duplicate rewordings, and lines cut mid-word at 80 characters, with no way to remove any of them. (1) **KNOWN** now lists up to five Soon tasks waiting 7+ days (`in Soon · "…" — waiting N days`, oldest first, dismissible via `revokedKnownItems` key `sn:<id>`); tasks deferred to Soon were previously invisible there. (2) **Lifecycle** — hypothesis records now carry `seenWeeks` (Monday keys) and `lastSeen`. Episodic items are replaced each run: anything the AI does not say again is tombstoned, and they expire after 7 days if runs stop. Semantic/procedural items are sent back as `stable_on_record` refs; the AI returns `{still:[refs], new:[…]}`; support in 3 separate weeks sets `confirmed`, 28 days without support fades the item. The panel shows only live episodic items and confirmed stable ones, and `status: 'confirmed'` finally feeds the focus-question context as intended. Pre-lifecycle records are pruned and tombstoned on the next run. (3) **"not me"** on each AI item removes it, tombstones its id, and records the text in the new `appMemory.rejectedHypotheses`; the prompt forbids restating any rejection and near-duplicates of one are dropped. Clear-all wipes it. (4) **Prompt** — every observation must contrast outcomes (finished vs released/returning, obligation vs chosen, worked on vs never started); naming what tasks are about is excluded. (5) **Length/duplicates** — cap raised 80 → 160 characters and cut on a word with an ellipsis only beyond it; a content-word overlap check treats rewordings as recurrence of the existing item. **Sync:** the same item re-supported on another device unions `seenWeeks` and keeps the later `lastSeen`; rejections union by text and respect the clear watermark. `memory-panel-test` adds abstraction-quality and lifecycle cases (verified failing on the old code); `dropbox-test` adds the cross-device lifecycle merge. |
| **2.90.54** | **Fix BUG-103: yesterday’s synced dismissal cannot hide today’s morning nudge.** `_DISMISS_SYNC` backed up per-day flags as bare `'1'` values, then merged any remote `'1'` into the receiving device’s current-date key. A snapshot saved after yesterday’s dismissal but pulled just after midnight could therefore suppress today’s strip while About still had its independently dated line. The backup now includes `per_day_dismiss_date` from `_localISO()`; merge applies the registry’s flags only when that source-local date equals today. Undated legacy snapshots are ignored rather than guessed from UTC `saved_at`; updated devices continue to share deliberate same-day dismissals. `dropbox-test` proved the old behavior failing, then covers prior-day, undated, valid-today, and outgoing payload cases. Existing local flags are preserved because an old mistaken flag cannot be distinguished from a deliberate tap. No nudge prompt, threshold, or timing changed. |
| **2.90.53** | **Fix BUG-104 + BUG-105: task enrichment (↗ web, ↩ Gmail) silently stopped working.** (1) Since v2.90.x (2026-09-14, `5ee16211`) `task-enrich` ran Claude Haiku 4.5 with `web_search_20260209`, a dynamic-filtering variant that only Opus 4.6+/Sonnet 4.6+/Sonnet 5 support; every call was rejected, the function broke out of its loop and answered `200 {card:null}`, and the client cached that as `no_result` for good. It now sends `web_search_20250305`, returns 502/429 on any provider error so nothing is cached, and the client versions its cache entries (`v: 2`) so unversioned `no_result` entries from the outage are retried once. (2) Since the 2026-09-05 boundary refactor (`906e71b6`) the Gmail classifier guarded on `typeof _aiGetProvider/_aiGetKey === 'function'` — globals that no longer exist — so it always sent provider `gemini` with an empty key, got a 400, and cached its regex fallback as the classification. It now reads both from `Today.use('connections')`, marks AI results `source: 'ai'`, stops caching the fallback, and reclassifies unmarked legacy entries once. Both suites encoded the bugs (Haiku + `web_search_20260209`; provider failure → `200 null`; an `ai-assist` mock that succeeded without a key); they now assert the real contracts and fail on the old code. |
