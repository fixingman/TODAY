| **2.80.5** | **Fix BUG-093: enrichment indicators no longer flash on tap on mobile.** `.task:hover .gmail-indicator` and `.task:hover .agent-indicator` were outside any `@media (hover: hover)` block — same class as BUG-079. Touch devices briefly fire `:hover` on tap, making ↩ and ↗ flash visible randomly when the user taps an enriched task. Fix: both hover rules wrapped in `@media (hover: hover)`. Mobile indicators are now visible only during the arrive animation at first enrichment and inside focus mode. |
| **2.80.3** | **Fix BUG-092: card aging restored on mobile.** BUG-079 (v2.66.1) scoped age-bucket opacity rules inside `@media (hover: hover)` to prevent an iOS tap-flash — on touch, `:hover` briefly fires, so the tapped task appeared bright (0.85) while aged neighbours stayed dim. That fix silently removed aging on mobile entirely. Correct fix: opacity rules are now global (young=0.75, mid=0.55, old=0.35 on both platforms); the `:hover` restore stays inside `@media (hover: hover)` so there is no hover rule for touch to misfire on. |

Corpus grows 119 → 123 (W14 / Sp16 / Su12 / Au10 / year-round 71). Smoke coverage locks the new count, attributions, and six-line ceiling. No storage or sync interfaces changed. |
| **2.80.4** | **Fix: stale premises in AI context — three leaks of the same class.** Reported from production: the morning nudge said a task was "still waiting after 56 days" when it had been completed the day before. (1) `_updateReturningTasksMemory` rebuilt `returningTasks` from `manualTasks` but never filtered `doneIds` — the only context builder in the app that didn't (`nudge.js:100/105/356`, `about.js:595/649`, `focus.js:313` all do). A task completed yesterday and still present in `manualTasks` kept its full age and was handed to the AI as waiting. Now skips `doneIds` and `pastTasks`, and skips them *before* the age buckets too, since a finished task is not ambient load — `taskAgeBuckets` was overcounting for the same reason. (2) A let-go obligation stayed under "Still pending" forever: `obligationHistory.done` was only ever set by `_memoryOnTaskComplete`, so an abandoned obligation persisted until the 90-day prune. Marked with a separate `letgo` flag rather than reusing `done` — a let-go is a real outcome and belongs in the completion-rate denominator, so marking it done would have inflated the rate it feeds. (3) `focus.js` filtered `doneIds` but not `pastTasks`, so a stale sync could offer an archived task to the focus question as part of "today's list". **Note on the class:** the model never hallucinated in any of these — it reported exactly what the context said. Stale-premise bugs are therefore invisible to prompt work, and better phrasing only produces a more convincing wrong sentence. Regression tests reproduce the production report directly and were verified to fail without the fix; one of them also caught the first patch landing in `_memoryOnTaskComplete` instead of `_memoryOnTaskLetgo`, because `insights.js` carries two identical `_kStopWords` declarations. Full suite 25/25. |
| **2.80.2** | **Test coverage for the 12 arc, and a guard gap it exposed.** Everything in 12a/12c had been verified only by hand in a browser — the category that rots silently, as `obligationHistory` (shipped unsynced in v2.78.0, invisible for a week) and the stale `reflectionForgetConfirm` test (red for ~14 versions) both demonstrated. Coverage added to the three suites that own each surface rather than a new file: **`dropbox-test`** — `taskOutcomes` / `spokenLines` / `obligationHistory` merges, union and dedup, same-day-different-outcome kept as a distinct event, 90-day prune, `done` flag OR'd, unknown `obligation` preserved as `null`; **`insights-test`** — `_memoryRecordOutcome` routing (done/letgo/soon_pull/revive each once, Soon-pull not also logging a let-go), focus resolved by id and by text fallback, no task text stored, `_memoryBackfillOutcomes` seeding/idempotence/`_legacy` skip/window exclusion and the two unknown-stays-unknown invariants, `_memoryRecordSpokenLine` kind storage and same-surface-per-day replacement; **`nudge-test`** — the pool payload carries evidence+contrast with no task-list or `_memoryForAI` leak, and cooldown, abstention and guard rejection each fall through to the task path. **Gap found by the new tests:** `_observationTextIsGrounded` guarded only the pool path, so an identity or causal claim was blocked on the rare path and waved through on the majority task-reading path. The guard now applies to both; a rejected line falls back to the rule-based text. Full suite 25/25. |
| **2.80.1** | **Feat: revive capture + one-time taskOutcomes backfill.** Two gaps found by asking what the pre-pool signals were worth keeping. (1) `_memoryOnRevive` now calls `_memoryRecordOutcome('revive', …)` — `design/Personalization.md` names Revive first among preferred lifecycle evidence and Phase 0 had captured done/letgo/soon_pull but missed it. (2) `_memoryBackfillOutcomes()` runs once (guarded by `appMemory.taskOutcomesBackfilled`) and seeds `taskOutcomes` from `recentCompletedTasks` plus the dated `letgoReasons` / `reviveReasons` day maps, 90-day window, `_legacy` buckets skipped. Without it the pool would sit silent for ~a month while weeks of dated history went unused. `obligationHistory` deliberately excluded as a source — its `date` is the add date, not the outcome date. **Backfill honesty:** `focusSessions` is unknown for reconstructed rows, so they carry `backfilled: true` and `focus-vs-obligation` excludes them — writing `0` would make "all focus went to chosen work" trivially true out of a missing field. `obligation` is unknown for let-go/revive rows, so they carry `obligation: null` and the partitions moved from truthiness to `=== true` / `=== false`; the old `!e.obligation` test would have filed every unknown as *chosen* and corrupted the completion-rate contrast. Six new unit tests (42 total) pin both invariants. Browser-verified: correct row shapes, `_legacy` skipped, 200-day-old row excluded, re-run idempotent, live revive recorded unflagged. |
| **2.80.0** | **Feat: 12c Phase 3 — the observation pool reaches the morning nudge.** First behaviour change of the arc. `_fetchPoolNudge()` runs before the task-reading path: it builds candidates from `appMemory.taskOutcomes`, filters them through `_observationNoveltyGate()` against `spokenLines`, and on a survivor sends the model **evidence + contrast only** — no task list, no `_memoryForAI` dump, nothing to choose between, because selection already happened in code. Measured payload 305 chars vs 2,702 for the old dump. Output passes `_observationTextIsGrounded(text, 30)`, a generalization of Sunday's guard (`_weekReflectionTextIsGrounded` is now a 26-word wrapper, behaviour unchanged); an identity or causal claim is rejected even when the model ignores the prompt, and the surface falls through rather than showing it. The shown line is recorded to `spokenLines` **with its `kind`**, which is what puts that kind on cross-surface cooldown. Abstention is per-surface: the nudge never goes silent, it falls back to the task-reading path and then to the rule-based line, because the morning is the signature beat. Candidates are rare by construction, so most mornings are unchanged. Browser-verified on a fresh origin: pool payload shape, cooldown skip, abstention fall-through, and guard rejection with nothing recorded. 12b's three instruction lines deliberately remain on the fallback path — they are the only guidance for the `_memoryForAI` dump that path still sends. Other four surfaces untouched. |
| **12c Phases 0–2** | **Observation pool groundwork — no version bump, no user-visible change.** Three commits landing after v2.79.2 with no CHANGELOG entry by design: the plan puts the entry with Phase 3, which is the first behaviour change. **Phase 0** adds `appMemory.taskOutcomes`, a rolling 90-day / 300-entry log of `{ id, date, outcome: done\|letgo\|soon_pull, obligation, focusSessions, reason? }` written at `_memoryOnTaskComplete`, `_memoryOnTaskLetgo` and `_memoryOnSoonPull`; `_memoryOnTaskLetgo` gains an optional `outcome` so the Soon-pull path produces one record, not two. Stores no task text — the text-fallback id is a djb2 hash, deterministic across devices. Merged in `dropbox.js` by `id\|outcome\|date`. Discovered by checking data availability first: three of the four approved candidate kinds were not computable, because every approved observation is a *windowed contrast* and `letgoReasons`/`soonPulls` were undated lifetime counters. **Phase 1** extends `assets/week-reflection-policy.js` rather than adding a module — splits `_buildWeekCandidates()` from `_buildWeekReflectionInsight()` (Sunday behaviour unchanged), adds `_buildOutcomeCandidates()` with four kinds (`focus-vs-obligation` 115, `obligation-completion` 105, `letgo-reason` 95, `soon-pullback` 88) and `_buildObservationCandidates()` as the ranked pool; renames `meaning` → `contrast` throughout, with `about.js` reading the new field and its prompt wording untouched. **Phase 2** adds `_observationNoveltyGate()` / `_observationGateExplain()` with per-kind, cross-surface cooldowns (21 days for month-window kinds, 7 for week-shaped) and a deliberately narrow age-as-content rule — a tenure claim drops, a "over 30 days" window statement survives. `spokenLines` entries gain an optional `kind` and the cap goes 30 → 120, because at one entry per surface per day a 30-entry cap let a kind leave a 21-day cooldown by eviction rather than by time. New `scripts/observation-pool-test.mjs`, 36 tests, registered in `test-all`. |
| **2.79.1** | **Fix: the same waiting task was described twice in AI context.** `neverStarted` is a strict subset of `returning`, so any 7+ day zero-session task was emitted under both "Tasks that keep waiting" and "Tasks not yet started despite being on the list", then a third time in the numbered task list. Found by intercepting a real nudge payload: one task appeared three times and was by far the most-repeated string in the prompt. A model choosing from ~12 unranked facts selects on salience, so repetition was effectively doing the selecting. Focus avoidance now rides as an inline marker ("never opened" at 7+ days, "not yet started" below) — same signal, one emission per task. |
