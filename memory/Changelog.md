| **2.90.18** | **Shift+Space now has an explicit capture trust boundary and a true hold lifecycle.** The initial v2.90.17 implementation called legacy `SpeechRecognition` directly; on common browsers that can send microphone audio to a browser-owned server even though TODAY has no configured connection, defaults to one result rather than a continuous held utterance, and stopped only when Space came up while Shift was still held. Otherwise it records one self-contained 45-second-maximum clip at 32 kbps and sends it through the existing `/transcribe` function using the user's configured Gemini key; no meeting-style chunks, browser-cloud fallback, stored audio, or stored transcript. Either Shift or Space release ends capture, as does window blur. The pill moves through Getting ready → Listening → Finding the words → Added, with visible empty, unavailable, and failure outcomes; its listening dot now uses the shared reduced-motion-aware WAAPI breath instead of a CSS loop. New `voice-capture-test.mjs` covers the local preference, one-blob fallback, modifier release order, guards, media cleanup, success, and failure. The default gate is now 36 non-live suites plus design lint: 37 checks. No storage, sync, provider-selection, or routing interface changed. |
