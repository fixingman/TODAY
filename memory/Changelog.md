| **2.37.3** | **Fix: meeting mode attribution — two real misses, wrong approach reverted.** Can's report: (1) unnamed self-commitments ("I'll send that") were sometimes missed entirely — the prompt required either explicit assignment by name or being addressed by name by someone else, so a task nobody named out loud defaulted to `mine:false` and, after v2.37.2, vanished with no way to recover it; (2) some items showed the user's own name as owner but weren't pre-selected — the model's `owner` and `mine` fields could disagree with each other. Reverted v2.37.2's hard client-side filter (hiding non-mine items was the wrong fix — it turned false negatives from recoverable-but-unselected into invisible). Real fix, two parts: (a) prompt now treats an unnamed first-person commitment ("I'll...", "let me...") as `${name}`'s by default — `${name}` is often never spoken aloud in their own meeting, so "unclear" was the wrong default; `mine:false` now requires a specific *other* named person as the clear owner; (b) server-side post-process safeguard in `meeting-extract.js` — if `owner` is empty or matches `${name}` (case-insensitive, checked against every name in the Connections list), `mine` is forced `true` regardless of what the model returned, so the two fields can no longer visibly contradict each other. Net effect: fewer real tasks missed, and the "unclear" bucket now leans toward showing you the item (pre-selected, easy to deselect) rather than assuming it isn't yours. |
