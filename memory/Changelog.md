| **2.92.5** | **Gmail enrichment, focus Ask, and touch reorder cues.** For “email to Gaia for reservation,” the regex fallback separates Gaia from the topic instead of searching for a correspondent named “Gaia for reservation”; explicit email tasks reclassify older AI false negatives and search even if the AI declines. An AI query without a Gmail operator is rejected; a valid AI query that finds no thread retries one person-plus-topic fallback, but Gmail auth/network/API errors do not trigger a misleading retry. The same path serves task insertion and focus-on-demand. A bounded local diagnostic (`Today.use('gmail').observationAudit()`) records stages and status codes, never task text, query, message content or credentials. Focus Ask now derives its hint and prompt context from the same task-history facts, removes generic/personal signals from the highlight, and asks one task-specific question rather than following a scenario lookup table. Task and habit row hover cues are guarded by `(hover: hover)` so a touch reorder does not leave a neighboring row visually selected. `gmail-test`, `focus-test`, and `drag-test` cover these changes; 39/39 suites pass. Live Gmail verification remains. |
| **2.92.4** | **Dream reading prompt, measured.** `scripts/dream-reading-eval.mjs` baseline on the v2.92.0 prompt: swap accuracy 100% (saturated — readings restate details, so it cannot rank prompts), specificity 3.42/5, usefulness 3.75/5, 12/12 readings with generic phrases; ~130-word image-by-image tours ending in disclaimers ("Take it gently…"), with guessed life context ("pressure at work"). The new `_DREAM_SYSTEM` (principles only): start from the detail that stands out, where a feeling does not fit what happened or someone or something is not what it should be; follow one or two threads; connect to waking life only as far as the dream points, no guesses about work, relationships, or circumstances; tentative through wording, not disclaimers; end with one question in the dream's own terms; ≤80 words. Head-to-head (`--versus`, order alternated, judge prefers substance over length): preferred 12/12, average 128 → 65 words; Can reviewed the paired readings and agreed. The judge's criteria overlap the prompt's aims, so the win rate is a signal, not proof. Both eval scripts now parse the escaped apostrophe in the prompt; `meeting-test` pins the new principles. |

| **2.92.1** | **Fix: AI prose cut at 200 characters or dropped; dream detection misread figurative speech.** Found by the first live run of `dream-live-test`. (1) `ai-assist` wrapped every non-JSON reply as `message: text.slice(0, 200)` and never set `content`, while every prose surface reads `content || message` — so dream readings, Gmail drafts, the Sunday reflection, Monday intention, morning nudge, focus question and memory text were all silently capped at 200 characters (the live reading ended mid-word, "Maybe there's a sen"). The fallback now also returns the full `content`; `message` keeps its 200-char shape for the suggestion chip. (2) The Claude branch read only `content[0].text`; Sonnet 5 thinks adaptively by default, so a leading thinking block produced an empty reply with HTTP 200 (the live figurative case). It now joins all text blocks and sends `thinking: {type: 'disabled'}`, matching the Gemini branch's `thinkingBudget: 0` for these short writing tasks. (3) `meeting-extract` read "work felt like a bad dream" as a dream account; the prompt now states the principle — a dream account narrates what was experienced while asleep; dreamlike waking events and ambitions called dreams are not. New offline `ai-assist-unit-test` (in the gate, 39 checks) pins full-length content, text-block joining, disabled thinking, unchanged JSON passthrough, and Gemini parity — verified failing on the old handler. `dream-live-test` now retries provider 503/429 with backoff. Live verification of (3) awaits a rerun with keys. |

| **2.91.1** | **Fix BUG-106: three more guards on functions that moved into modules.** The BUG-105 pattern — `typeof _x === 'function' ? | **2.91.0** | **Memory panel: AI observations have a lifecycle; KNOWN lists waiting Soon tasks.** Can: KNOWN showed only the counts line, and EPISODIC had grown into a long mix of topic summaries ("house painting", "invoices"), near-duplicate rewordings, and lines cut mid-word at 80 characters, with no way to remove any of them. (1) **KNOWN** now lists up to five Soon tasks waiting 7+ days (`in Soon · "…" — waiting N days`, oldest first, dismissible via `revokedKnownItems` key `sn:<id>`); tasks deferred to Soon were previously invisible there. (2) **Lifecycle** — hypothesis records now carry `seenWeeks` (Monday keys) and `lastSeen`. Episodic items are replaced each run: anything the AI does not say again is tombstoned, and they expire after 7 days if runs stop. Semantic/procedural items are sent back as `stable_on_record` refs; the AI returns `{still:[refs], new:[…]}`; support in 3 separate weeks sets `confirmed`, 28 days without support fades the item. The panel shows only live episodic items and confirmed stable ones, and `status: 'confirmed'` finally feeds the focus-question context as intended. Pre-lifecycle records are pruned and tombstoned on the next run. (3) **"not me"** on each AI item removes it, tombstones its id, and records the text in the new `appMemory.rejectedHypotheses`; the prompt forbids restating any rejection and near-duplicates of one are dropped. Clear-all wipes it. (4) **Prompt** — every observation must contrast outcomes (finished vs released/returning, obligation vs chosen, worked on vs never started); naming what tasks are about is excluded. (5) **Length/duplicates** — cap raised 80 → 160 characters and cut on a word with an ellipsis only beyond it; a content-word overlap check treats rewordings as recurrence of the existing item. **Sync:** the same item re-supported on another device unions `seenWeeks` and keeps the later `lastSeen`; rejections union by text and respect the clear watermark. `memory-panel-test` adds abstraction-quality and lifecycle cases (verified failing on the old code); `dropbox-test` adds the cross-device lifecycle merge. |
| **2.90.54** | **Fix BUG-103: yesterday’s synced dismissal cannot hide today’s morning nudge.** `_DISMISS_SYNC` backed up per-day flags as bare `'1'` values, then merged any remote `'1'` into the receiving device’s current-date key. A snapshot saved after yesterday’s dismissal but pulled just after midnight could therefore suppress today’s strip while About still had its independently dated line. The backup now includes `per_day_dismiss_date` from `_localISO()`; merge applies the registry’s flags only when that source-local date equals today. Undated legacy snapshots are ignored rather than guessed from UTC `saved_at`; updated devices continue to share deliberate same-day dismissals. `dropbox-test` proved the old behavior failing, then covers prior-day, undated, valid-today, and outgoing payload cases. Existing local flags are preserved because an old mistaken flag cannot be distinguished from a deliberate tap. No nudge prompt, threshold, or timing changed. |
| **2.90.53** | **Fix BUG-104 + BUG-105: task enrichment (↗ web, ↩ Gmail) silently stopped working.** (1) Since v2.90.x (2026-09-14, `5ee16211`) `task-enrich` ran Claude Haiku 4.5 with `web_search_20260209`, a dynamic-filtering variant that only Opus 4.6+/Sonnet 4.6+/Sonnet 5 support; every call was rejected, the function broke out of its loop and answered `200 {card:null}`, and the client cached that as `no_result` for good. It now sends `web_search_20250305`, returns 502/429 on any provider error so nothing is cached, and the client versions its cache entries (`v: 2`) so unversioned `no_result` entries from the outage are retried once. (2) Since the 2026-09-05 boundary refactor (`906e71b6`) the Gmail classifier guarded on `typeof _aiGetProvider/_aiGetKey === 'function'` — globals that no longer exist — so it always sent provider `gemini` with an empty key, got a 400, and cached its regex fallback as the classification. It now reads both from `Today.use('connections')`, marks AI results `source: 'ai'`, stops caching the fallback, and reclassifies unmarked legacy entries once. Both suites encoded the bugs (Haiku + `web_search_20260209`; provider failure → `200 null`; an `ai-assist` mock that succeeded without a key); they now assert the real contracts and fail on the old code. |
